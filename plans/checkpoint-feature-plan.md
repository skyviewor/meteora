# 检查点：面向科研工作流的状态恢复与可重放数据管理

## Summary

提供用户可理解的“检查点、恢复、实验分支、差异”能力，界面和文档不出现 Git 概念。底层使用项目内私有 Git 对受控的小文件实现精确版本恢复；大数据不复制、不纳入版本库，只保存数据清单、血缘与可重放信息。

## Implementation Status

第一阶段已实现：

- 检查点核心存储、独立文件历史、完整/部分 SHA-256 指纹和 Git 不可用时的清单降级。
- `/checkpoint`、`/checkpoints`、`/restore`、`/experiment` 命令，以及 Agent 的创建、列表、差异和实验分支能力。
- 检查点列表默认隐藏恢复前自动创建的保护记录，`/checkpoints all` 可按需查看完整历史。
- `/checkpoint delete <ID>` 经确认删除单个检查点，自动修复当前指针和后续检查点的父级关系。
- 加密会话快照、模型摘要、脱敏工具账本、恢复前安全检查点和恢复后新会话/实验分支。
- `data/`、`literature/` 和超过 50 MiB 的文件仅记录引用；密钥文件不进入清单或文件历史。

后续阶段待实现：

- 在所有变更工具的执行边界记录结构化父输入、处理参数、质量摘要和可重放状态。
- 外部 Shell 变更标记、恢复前强制重扫，以及基于血缘的可重建缓存复用与确认清理。
- 私有历史损坏、恢复中断和会话解密失败的故障注入测试与修复引导。

## Key Changes

- 新增 `CheckpointManager`，在首次创建检查点时初始化 `.aero/history.git` 私有版本库及 `.aero/checkpoints/` 元数据目录；不读取、修改、提交或推送用户已有的 `.git` 仓库。
- 新增检查点命令与 Agent 工具：
  - `/checkpoint [名称]`：保存会话快照、工作区清单、数据血缘与受控文件版本。
  - `/checkpoints`：按时间列出检查点及其数据/产物摘要。
  - `/restore <检查点>`：先显示差异和恢复能力，再经确认恢复。
  - `/experiment [名称]`：从当前检查点开启新的实验分支；用户仅看到“实验分支”。
- 检查点包含：
  - 加密的对话消息、模型配置摘要、计划文件和当前会话标识；
  - 数据与产物清单：路径、格式、大小、来源、父产物、处理参数、质量摘要；
  - 文件指纹：脚本、配置与小型产物使用完整 SHA-256；大文件使用大小、修改时间和首尾块指纹，并标记为“可验证但非完整快照”；
  - Agent 工具调用账本，记录成功操作的参数、输出文件、父输入与可重放状态。
- 受控文件分层：
  - **精确恢复**：配置、脚本、计划、Markdown/LaTeX、以及不超过 50 MiB 的图表、表格和文本产物，提交到私有版本库。
  - **引用恢复**：原始下载数据、大型 NetCDF/GRIB 和大型衍生数据仅写入清单；检查点持有其引用，不复制数据。
  - **可重建缓存**：有完整父输入和处理参数的中间产物标记为可清理；不自动删除，用户确认后才清理未被当前或固定检查点引用的缓存。
- 恢复语义固定为：
  - 对话和计划精确恢复，并自动保存当前状态为安全检查点；
  - 受控小文件精确恢复；
  - 大数据不覆盖、不删除、不复制，只切换活动检查点引用并报告“匹配、缺失、已变更、可重放”；
  - 恢复后的继续操作自动进入新实验分支，保留原检查点之后的历史。
- 在 Agent 运行时拦截并记录下载、裁剪、转换、文件编辑、删除、本地入库与运行脚本等变更操作。无法可靠识别输出的 Shell 操作标为“外部变更”，恢复前必须重新扫描工作区并提示用户。
- 新增“检查点差异”视图：展示代码/计划变更、数据与图件的新增/缺失/指纹变化、可恢复与仅可重放的项目；所有覆盖操作沿用现有确认机制。
- Git 不可用时仍允许创建“会话 + 数据清单”检查点，但明确标记不能精确恢复受控文件，并提供不包含 Git 术语的环境修复提示。

## Test Plan

- 检查点可精确恢复加密会话、计划、配置和受控文本文件；恢复前状态自动保留。
- 已有用户 Git 仓库时，创建、恢复和实验分支均不改变其提交历史、分支或远端配置。
- 大型文件创建检查点后不产生副本；恢复时正确报告匹配、缺失及指纹变化。
- 相同输入和参数的可重建产物复用缓存；清理仅删除无活动/固定检查点引用的可重建项。
- 多次恢复、恢复中断、私有版本库损坏、Git 不可用、会话解密失败和外部 Shell 变更均安全失败且不覆盖用户文件。
- Agent 工具账本正确记录数据下载、裁剪、本地扫描确认、文件编辑和删除；差异视图可由账本与清单复原。

## Assumptions

- 首版在用户手动创建检查点时才初始化私有版本库；后续可增加高风险操作前的自动安全检查点。
- 不使用 Git LFS，不将大数据提交到任何版本库，也不自动同步到远端。
- 原始数据默认不可变；后续处理应生成新产物并记录父数据与参数，避免原地修改。
- 自动清理默认关闭；磁盘空间不足时只提示并给出可清理候选，不擅自删除数据。
